# SDD 系统使用指南

## 概述

SDD (Specification-Driven Development) 系统是为Admin.NET Pro项目设计的规范化开发框架，强调以项目宪法为指导，确保开发活动的规范性和一致性。

## 核心理念

### 🏛️ 宪法至上
项目宪法是所有开发活动的最高指导原则，任何开发决策都必须符合宪法要求。

### 📋 规范驱动
所有开发活动都始于清晰的需求和规范，确保开发方向的正确性。

### 🎯 质量内建
质量是设计出来的，不是测试出来的，在每个开发阶段都内建质量检查点。

## 系统架构

### 核心组件

1. **项目宪法** (`_sdd/PROJECT_CONSTITUTION.md`)
   - 项目的根本指导原则
   - 技术原则和质量标准
   - 开发流程和团队协作规范

2. **SDD编排器** (`/sdd` 命令)
   - 所有SDD活动的统一入口
   - 协调各专业代理的工作
   - 提供方法咨询和工作流指导

3. **专业代理**
   - **初始化架构师** (`init-architect`): 项目初始化和框架建立
   - **规划专家** (`planner`): 需求分析和技术方案制定
   - **实现专家** (`implementer`): 代码实现和质量保证
   - **分析专家** (`analyzer`): 代码质量分析和架构评估
   - **调试专家** (`debugger`): 问题诊断和解决方案设计
   - **学习专家** (`learner`): 经验总结和知识库更新
   - **宪法守护者** (`constitution-guardian`): 宪法管理和合规性监督

## 核心命令

### 基础命令
- `*help` - 显示所有可用命令
- `*agent [名称]` - 转换为专业代理
- `*task [名称]` - 运行特定任务
- `*checklist [名称]` - 执行检查清单
- `*status` - 显示当前SDD上下文

### 工作流命令
- `*init` - 初始化SDD框架
- `*specify` - 创建功能规范
- `*plan` - 创建技术计划
- `*implement` - 执行开发任务
- `*analyze` - 分析质量架构
- `*learn` - 捕获经验教训

### 宪法管理命令
- `*constitution` - 项目宪法管理
- `*compliance` - 宪法合规性检查
- `*guardian` - 激活宪法守护者
- `*standards` - 标准执行监督

### Admin.NET专用命令

## 开发工作流

### 标准SDD工作流

#### 阶段1: 项目初始化
1. 激活SDD编排器: `/sdd`
2. 转换为初始化架构师: `*agent init-architect`
3. 创建项目宪法: `*create-constitution`
4. 设置SDD框架: `*setup-sdd-framework`

#### 阶段2: 需求规划
1. 转换为规划专家: `*agent planner`
2. 创建功能规范: `*specify`
3. 制定技术计划: `*plan`
4. 任务分解: `*task-decomposition`

#### 阶段3: 开发实现
1. 转换为实现专家: `*agent implementer`
2. 执行开发任务: `*implement`
3. 代码审查: `*execute-checklist`
4. 质量检查: `*quality-analysis`

#### 阶段4: 质量保证
1. 转换为分析专家: `*agent analyzer`
2. 质量分析: `*analyze`
3. 架构评估: `*architecture-review`
4. 性能分析: `*performance-analysis`

#### 阶段5: 宪法合规检查
1. 激活宪法守护者: `*agent constitution-guardian`
2. 合规性检查: `*check-compliance`
3. 标准执行监督: `*enforce-standards`
4. 改进建议: `*suggest-improvements`

#### 阶段6: 经验总结
1. 转换为学习专家: `*agent learner`
2. 经验捕获: `*lessons-capture`
3. 最佳实践总结: `*best-practices`
4. 知识库更新: `*update-knowledge-base`

### API开发工作流

#### 后端开发
1. 实现API接口和业务逻辑
2. 配置Swagger文档生成
3. 确保API符合RESTful规范

## 项目宪法管理

### 宪法结构
```
PROJECT_CONSTITUTION.md
├── 项目愿景
├── 核心价值观
├── 技术原则
├── 质量标准
├── 开发流程
├── 团队协作原则
├── 成功指标
└── 附录
```

### 宪法更新流程
1. **识别更新需求**: 项目发展需要新的原则或标准
2. **草案制定**: 宪法守护者起草更新方案
3. **团队评审**: 团队成员讨论和评审
4. **最终确认**: 项目负责人确认批准
5. **版本发布**: 更新宪法版本并通知团队

### 合规性检查
1. **定期检查**: 每个SDD阶段结束时
2. **专项检查**: 重大决策或变更时
3. **全面审查**: 项目里程碑节点

## 质量保证机制

### 检查清单系统
- **需求检查清单**: 确保需求完整和清晰

- **知识库更新**: 持续更新知识库和文档

## 常见问题

### Q: 如何开始使用SDD系统？
A: 首先运行 `/sdd` 激活SDD编排器，然后使用 `*agent init-architect` 开始项目初始化。

### Q: 项目宪法可以修改吗？
A: 可以，但需要经过正式的更新流程，包括草案制定、团队评审、最终确认等步骤。

### Q: 如何确保团队遵循宪法？
A: 通过宪法守护者代理的监督、定期合规性检查、质量门禁机制等方式确保。

### Q: SDD系统适用于什么类型的项目？
A: 特别适用于企业级应用、团队协作项目、长期维护项目和质量敏感项目。

### Q: 如何处理宪法与实际需求的冲突？
A: 首先通过宪法守护者进行分析，如果确实需要调整，按照宪法更新流程进行修改。
