## 用户输入

```text
$ARGUMENTS
```

你必须考虑用户输入后再继续（如果不为空）。

## 概述

实现执行命令按照任务清单执行所有开发任务，将技术计划转换为实际的工作代码。这个命令会：

1. **任务分析**：理解任务清单和执行顺序
2. **环境准备**：验证开发环境和依赖
3. **任务执行**：按顺序和依赖关系执行任务
4. **质量验证**：确保每个任务的质量标准

## 执行流程

### 1. 执行前检查

#### 检查清单状态
- 扫描 `_sdd/specs/[feature-name]/checklists/` 目录
- 检查所有检查清单的完成状态
- 生成状态报告：

```markdown
| 检查清单 | 总数 | 已完成 | 未完成 | 状态 |
|----------|------|--------|--------|------|
| requirements.md | 12 | 12 | 0 | ✓ PASS |
| design.md | 8 | 5 | 3 | ✗ FAIL |
| security.md | 6 | 6 | 0 | ✓ PASS |
```

#### 环境验证
- 检查 Node.js/Python 版本
- 验证数据库连接
- 确认依赖包安装状态
- 检查 Git 状态

#### 文件忽略配置
根据技术栈创建忽略文件：
- `.gitignore` - Git 忽略文件
- `.dockerignore` - Docker 忽略文件
- `.eslintignore` - ESLint 忽略文件
- `.prettierignore` - Prettier 忽略文件

### 2. 上下文加载

#### 必读文档
- **任务清单**：`tasks.md`（执行计划和依赖关系）
- **技术计划**：`plan.md`（技术栈和架构）
- **功能规范**：`spec.md`（用户需求和验收标准）

#### 可选文档
- **数据模型**：`data-model.md`（实体和关系）
- **API 契约**：`contracts/`（接口定义）
- **调研结果**：`research.md`（技术决策）
- **快速指南**：`quickstart.md`（验证场景）

### 3. 任务解析

#### 任务结构分析
```markdown
- [ ] T001 创建项目结构
- [ ] T005 [P] 实现认证中间件
- [ ] T012 [US1] 创建用户模型
- [ ] T014 [US1] 实现用户服务
```

#### 解析结果
- **总任务数**：45 个
- **阶段分布**：设置 12 个，基础 8 个，用户故事 25 个
- **并行任务**：15 个（标记为 [P]）
- **用户故事任务**：25 个（标记为 [USn]）

### 4. 执行策略

#### 阶段执行
1. **阶段 1**：项目设置（必须完成）
2. **阶段 2**：基础组件（阻塞后续任务）
3. **阶段 3+**：用户故事（按优先级）
4. **最终阶段**：集成和优化

#### 并行执行规则
- **串行任务**：按顺序执行，等待完成
- **并行任务**：可以同时执行，独立文件
- **同文件任务**：必须串行执行
- **测试优先**：测试任务在实现任务前执行

#### 错误处理
- **非并行任务失败**：停止执行，报告错误
- **并行任务失败**：继续其他任务，报告失败
- **环境问题**：提供修复建议
- **依赖问题**：检查并安装依赖
