## 用户输入

```text
$ARGUMENTS
```

你必须考虑用户输入后再继续（如果不为空）。

## 概述

任务分解命令将技术计划转换为具体、可执行的任务列表。这个命令会：

1. **计划分析**：理解技术方案和实现步骤
2. **任务分解**：按用户故事组织具体任务
3. **依赖分析**：确定任务间的依赖关系
4. **并行规划**：识别可并行执行的任务

## 执行流程

### 1. 上下文加载
- 读取技术计划：`_sdd/specs/[feature-name]/plan.md`
- 读取功能规范：`spec.md`
- 检查相关文档：`data-model.md`, `contracts/`, `research.md`

### 2. 任务分析

#### 从技术计划提取
- **技术栈**：框架、库、工具
- **架构组件**：前端、后端、数据库、缓存
- **API 端点**：需要实现的接口
- **数据模型**：需要创建的表和实体

#### 从功能规范提取
- **用户故事**：按优先级排序的用户需求
- **验收标准**：每个故事的完成条件
- **成功指标**：可衡量的目标

#### 从设计文档提取
- **数据模型**：具体的表结构和关系
- **API 契约**：详细的接口定义
- **调研结果**：技术决策和理由

### 3. 任务组织策略

#### 按阶段组织
1. **阶段 1**: 项目设置（基础设施）
2. **阶段 2**: 基础组件（共享依赖）
3. **阶段 3+**: 用户故事（按优先级）
4. **最终阶段**: 集成和优化

#### 按用户故事组织
每个用户故事包含：
- **测试用例**（如果要求）
- **数据层**：模型、仓库
- **业务层**：服务、逻辑
- **接口层**：API、控制器
- **前端层**：组件、页面

### 4. 任务格式规范

#### 任务格式
每个任务必须遵循以下格式：
```markdown
- [ ] [TaskID] [P?] [Story?] 任务描述 + 文件路径
```

#### 格式说明
- **复选框**：`- [ ]`（Markdown 复选框）
- **任务 ID**：`T001, T002, T003...`（按执行顺序）
- **并行标记**：`[P]`（仅可并行任务）
- **故事标签**：`[US1], [US2], [US3]`（仅用户故事任务）
- **文件路径**：具体的文件路径

#### 示例
```markdown
- [ ] T001 创建项目结构
- [ ] T005 [P] 实现认证中间件 src/middleware/auth.js
- [ ] T012 [US1] 创建用户模型 src/models/User.js
- [ ] T014 [US1] 实现用户服务 src/services/UserService.js
```

### 5. 依赖关系分析

#### 串行依赖
- 项目设置 → 基础组件 → 用户故事
- 数据模型 → 仓库层 → 服务层 → 接口层
- 测试用例 → 实现代码 → 集成测试

#### 并行机会
- 不同模块的开发任务
- 独立的组件实现
- 并行的测试编写

### 6. 时间估算

#### 估算标准
- **简单任务**：15-30 分钟
- **中等任务**：30-90 分钟
- **复杂任务**：90-180 分钟
- **集成任务**：120-240 分钟

#### 估算因素
- 代码复杂度
- 依赖关系
- 测试要求
- 集成难度

### 7. 质量检查点

#### 阶段检查点
- **阶段 1**：项目结构完整，环境可运行
- **阶段 2**：基础组件可用，API 可访问
- **用户故事**：功能完整，测试通过
- **最终阶段**：系统集成，性能达标

#### 任务检查点
- 每个任务完成后标记为 `[X]`
- 每个阶段完成后进行集成测试
- 发现问题及时调整后续任务

## 使用示例

### 基本任务分解
```bash
/sdd.tasks
```

### 带参数的任务分解
```bash
/sdd.tasks 使用 TDD 开发模式，重视测试覆盖率
```

### 更新任务清单
```bash
/sdd.tasks 更新任务清单，增加性能优化任务
```

## 注意事项

1. **任务粒度适中**，既不能太粗也不能太细
2. **明确依赖关系**，避免循环依赖
3. **合理估算时间**，考虑不确定性
4. **支持并行执行**，提高开发效率
5. **包含质量检查**，确保交付质量

## 相关命令

- `/sdd.plan` - 制定技术计划
- `/sdd.implement` - 执行任务实现
- `/sdd.checklist` - 生成质量检查清单
- `/sdd.analyze` - 分析任务一致性
