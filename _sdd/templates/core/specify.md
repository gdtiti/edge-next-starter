## 用户输入

```text
$ARGUMENTS
```

你必须考虑用户输入后再继续（如果不为空）。

## 概述

规范制定命令将模糊的用户需求转换为清晰、可测试的功能规范。这个命令会：

1. **需求分析**：理解用户想要实现的功能
2. **规范生成**：使用模板创建结构化规范
3. **质量检查**：确保规范的完整性和一致性
4. **澄清机制**：识别并标记需要进一步澄清的部分

## 执行流程

### 1. 需求理解
从用户输入中提取：
- **核心功能**：用户想要实现什么
- **目标用户**：为谁解决问题
- **业务价值**：为什么需要这个功能
- **使用场景**：在什么情况下使用

### 2. 功能命名
生成一个简洁的功能名称（2-4个单词）：
- 提取关键概念
- 使用动词-名词格式
- 保持技术准确性
- 示例：
  - "用户登录系统" → "user-authentication"
  - "商品搜索功能" → "product-search"
  - "订单管理系统" → "order-management"

### 3. 规范目录创建
- 创建功能规范目录：`_sdd/specs/[feature-name]/`
- 初始化规范文件：`spec.md`
- 创建检查清单目录：`checklists/`

### 4. 规范内容生成

#### 用户故事提取
根据用户输入生成用户故事：
```
作为 [用户类型]
我希望 [功能目标]
以便 [业务价值]
```

#### 场景分析
识别主要使用场景：
- 正常流程
- 异常处理
- 边界条件

#### 功能需求定义
将用户需求转换为具体的功能需求：
- 核心功能
- 辅助功能
- 约束条件

#### 成功标准制定
定义可衡量的成功指标：
- 用户层面指标
- 技术层面指标
- 业务层面指标

### 5. 澄清标记
对于不明确的部分，使用澄清标记：
```
[NEEDS CLARIFICATION: 具体问题]
```

**澄清限制**：
- 最多标记 3 个关键问题
- 优先级：范围 > 安全 > 用户体验 > 技术细节
- 为每个问题提供可能的解决方案

### 6. 质量验证
检查规范的完整性：
- [ ] 用户故事清晰明确
- [ ] 功能需求可测试
- [ ] 成功标准可衡量
- [ ] 没有技术实现细节
- [ ] 澄清问题合理且必要

### 7. 检查清单生成
创建需求质量检查清单：
```markdown
# 需求质量检查清单：[FEATURE_NAME]

## 内容质量
- [ ] 没有实现细节（语言、框架、API）
- [ ] 专注于用户价值和业务需求
- [ ] 面向非技术相关方编写
- [ ] 所有必填部分已完成

## 需求完整性
- [ ] 没有 [NEEDS CLARIFICATION] 标记
- [ ] 需求可测试且明确
- [ ] 成功标准可衡量
- [ ] 成功标准与技术无关
- [ ] 所有验收场景已定义
- [ ] 边界情况已识别
- [ ] 范围明确界定
- [ ] 依赖和假设已识别
```

## 使用示例

### 基本功能规范
```bash
/sdd.specify 我想要一个用户登录系统，支持邮箱和密码登录
```

### 复杂功能规范
```bash
/sdd.specify 创建一个商品搜索功能，用户可以按关键词、分类、价格范围搜索，支持排序和筛选
```

### 更新现有规范
```bash
/sdd.specify 更新用户认证功能，增加双因素认证
```

## 注意事项

1. **专注于 WHAT 和 WHY**，避免 HOW
2. **面向业务相关方**，而非技术人员
3. **确保需求可测试**，避免模糊表述
4. **限制澄清数量**，最多 3 个关键问题
5. **使用合理默认值**，减少不必要的澄清
