---

## 用户输入

```text
$ARGUMENTS
```

你必须考虑用户输入后再继续（如果不为空）。

## 概述

宪法制定命令用于建立项目的根本性规则和原则。这个命令会：

1. **加载现有宪法**：读取 `_sdd/memory/constitution.md`
2. **分析用户输入**：理解用户想要制定或修改的原则
3. **更新宪法内容**：根据用户输入更新宪法模板
4. **验证一致性**：确保宪法与其他模板的一致性
5. **生成报告**：输出宪法更新结果和影响分析

## 执行流程

### 1. 初始化
- 检查 `_sdd/memory/constitution.md` 是否存在
- 如果不存在，从 `_sdd/templates/constitution-template.md` 创建基础宪法
- 读取现有宪法内容

### 2. 分析用户输入
如果用户提供了输入 `$ARGUMENTS`：
- 解析用户想要制定的原则类型
- 识别技术栈偏好
- 理解开发约束条件
- 提取团队价值观

### 3. 宪法内容生成
根据用户输入和项目上下文：

#### 如果用户输入为空（交互式模式）：
提出以下问题来引导用户制定宪法：

**项目愿景**：
- 你的项目要解决什么问题？
- 项目的长期目标是什么？
- 目标用户群体是谁？

**核心原则**（至少选择 3 个）：
- 代码质量优先 vs 快速交付
- 安全性优先 vs 用户体验优先  
- 技术创新 vs 稳定性优先
- 性能优先 vs 开发效率
- 可维护性 vs 功能丰富性

**技术约束**：
- 必须使用的技术栈？
- 禁止使用的技术？
- 性能要求？
- 安全要求？

**开发规范**：
- 测试覆盖率要求？
- 代码审查流程？
- 分支管理策略？
- 文档要求？

#### 如果用户输入不为空（直接模式）：
- 从用户输入中提取关键信息
- 填充宪法模板的相应部分
- 对缺失的部分使用合理默认值

### 4. 宪法更新
- 替换宪法模板中的占位符
- 更新版本号和日期
- 确保所有必填部分都有内容

### 5. 一致性检查
- 检查宪法与其他模板的一致性
- 更新相关模板以反映新的宪法约束
- 生成同步影响报告

### 6. 输出结果
- 显示宪法更新摘要
- 列出主要变更
- 提供下一步建议

## 输出格式

### 成功输出
```markdown
# 🎯 项目宪法更新完成

## 宪法信息
- **版本**: v1.0.0
- **制定日期**: 2024-01-01
- **状态**: 生效

## 核心原则
1. **代码质量优先**: 所有代码必须通过代码审查和测试
2. **安全第一**: 所有功能必须通过安全评估
3. **用户体验至上**: 所有设计必须以用户为中心

## 技术约束
- **前端框架**: React 18+
- **后端框架**: Node.js + Express
- **数据库**: PostgreSQL
- **测试覆盖率**: 最低 80%

## 同步影响报告
- ✅ 计划模板已更新
- ✅ 规范模板已更新
- ✅ 任务模板已更新

## 下一步建议
1. 使用 `/sdd.specify` 创建功能规范
2. 使用 `/sdd.plan` 制定技术计划
3. 使用 `/sdd.tasks` 分解开发任务
```

### 错误输出
```markdown
# ❌ 宪法制定失败

## 错误信息
- 缺少项目愿景描述
- 核心原则数量不足（需要至少 3 个）

## 修复建议
1. 请提供项目的愿景描述
2. 请至少定义 3 个核心原则
3. 请重新运行命令
```

## 使用示例

### 交互式模式
```bash
/sdd.constitution
```

### 直接模式
```bash
/sdd.constitution 创建一个高质量的用户管理系统，重视代码质量和安全性，使用 React 和 Node.js 技术栈
```

### 更新模式
```bash
/sdd.constitution 更新宪法，增加性能要求：响应时间小于 200ms
```

## 注意事项

1. **宪法是项目的根本文档**，所有后续开发都必须遵守
2. **技术约束一旦确定**，不应轻易更改
3. **核心原则应该简洁明确**，避免模糊表述
4. **定期审查宪法**，确保其仍然适合项目发展
