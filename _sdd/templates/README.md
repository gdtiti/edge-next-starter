## 🎯 模块职责

### Core (核心流程)
负责 SDD 方法论的核心流程模板，包括：
- 项目宪法制定
- 功能规范制定
- 技术计划制定
- 任务分解
- 实现执行

### Quality (质量保证)
负责质量检查和验证模板，包括：
- 需求质量检查
- 设计质量检查
- 实现质量检查

### Patterns (设计模式)
负责可重用的设计模式和调试模板，包括：
- API 误用调试模式
- UX 优化模式
- 根因分析模板
- 方案验证模板
- 知识库模板

### Tools (工具命令)
负责各种工具和辅助命令模板，包括：
- 分析工具
- 澄清工具
- 检查清单生成
- 调试工具
- 初始化工具
- MCP 工具

## 🔄 使用指南

### 模板选择原则
1. **核心流程**: 使用 `core/` 目录下的模板
2. **质量检查**: 使用 `quality/` 目录下的检查清单
3. **常见问题**: 使用 `patterns/` 目录下的模式模板
4. **工具操作**: 使用 `tools/` 目录下的命令模板

### 模板命名规范
- 使用英文命名，确保跨平台兼容
- 采用清晰的动词/名词组合
- 保持简洁但具有描述性

### 模板维护原则
- 每个模板专注于特定职责
- 避免模板间的功能重叠
- 定期更新和完善模板内容
- 保持模板与实际使用场景的同步

## 📊 重构效果

### 改进前问题
- 职责混合：commands 和 checklists 功能重叠
- 分类不清：调试模板分散在多个目录
- 维护困难：相似功能的模板分布在不同位置

### 重构后优势
- ✅ **职责清晰**：每个目录负责特定类型的模板
- ✅ **易于维护**：相关模板集中管理
- ✅ **符合SRP**：单一职责原则得到严格遵循
- ✅ **便于扩展**：新增模板有明确的归属位置
- ✅ **提升效率**：减少寻找模板的时间

## 🚀 后续优化
