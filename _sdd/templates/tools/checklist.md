## 用户输入

```text
$ARGUMENTS
```

你必须考虑用户输入后再继续（如果不为空）。

## 概述

检查清单命令为 SDD 的各个阶段生成质量检查清单，确保每个阶段的输出都符合质量标准。这个命令会：

1. **阶段识别**：确定当前所处的开发阶段
2. **标准制定**：根据项目宪法制定质量标准
3. **清单生成**：为每个阶段生成详细的检查清单
4. **验证机制**：提供检查结果的验证方法

## 执行流程

### 1. 阶段识别
根据现有文档确定当前阶段：
- **Constitution 阶段**：只有 `constitution.md`
- **Specification 阶段**：有 `spec.md`
- **Planning 阶段**：有 `plan.md`
- **Tasks 阶段**：有 `tasks.md`
- **Implementation 阶段**：有实现代码

### 2. 质量标准制定

#### 基于 Project Constitution
- **代码质量标准**：测试覆盖率、代码审查
- **性能标准**：响应时间、并发量
- **安全标准**：认证、授权、数据保护
- **文档标准**：API 文档、用户手册

#### 基于行业最佳实践
- **可维护性**：代码结构、命名规范
- **可扩展性**：架构设计、接口设计
- **可测试性**：测试策略、覆盖率
- **可部署性**：部署流程、环境配置

- [ ] 需求可测试且明确

- [ ] 成功标准与技术无关

- [ ] 范围明确界定
- [ ] 依赖和假设已识别

### 4. 验证机制

#### 自动化检查
- **代码风格检查**：ESLint, Prettier
- **类型检查**：TypeScript, mypy
- **测试覆盖率**：Jest, pytest
- **安全扫描**：npm audit, safety

#### 手动检查
- **代码审查**：Pull Request Review
- **架构审查**：技术设计评审
- **安全审查**：安全专家评审
- **性能审查**：性能测试报告

## 使用指南

### 检查流程
1. **逐项检查**：按照清单逐项验证
2. **记录结果**：标记每项的检查结果
3. **问题跟踪**：记录发现的问题
4. **修复验证**：修复问题后重新检查

### 检查结果格式
```markdown
| 检查项 | 状态 | 负责人 | 完成日期 | 备注 |
|--------|------|--------|----------|------|
| 需求完整性 | ✅ | 产品经理 | 2024-01-01 | - |
| 验收标准 | ✅ | 产品经理 | 2024-01-01 | - |
| 技术无关性 | ⚠️ | 技术负责人 | 2024-01-02 | 需要调整表述 |
```

## 质量标准

### 通过标准
- **需求阶段**: 所有检查项 100% 通过
- **设计阶段**: 所有检查项 95% 以上通过
- **实现阶段**: 所有检查项 90% 以上通过

### 质量等级
- **优秀**: 95% 以上检查项通过
- **良好**: 85-94% 检查项通过
- **一般**: 70-84% 检查项通过
- **需改进**: 低于 70% 检查项通过

## 下一步建议
1. 开始执行检查清单
2. 记录检查结果
3. 修复发现的问题
4. 使用 `/sdd.analyze` 重新分析质量
```

## 使用示例

### 生成所有检查清单
```bash
/sdd.checklist
```

### 生成特定阶段检查清单
```bash
/sdd.checklist --stage requirements
```

### 生成特定类型检查清单
```bash
/sdd.checklist --type security
```

### 更新现有检查清单
```bash
/sdd.checklist --update
```

## 注意事项

1. **标准一致性**：检查清单必须与项目宪法一致
2. **可操作性**：每个检查项都应该可验证
3. **完整性**：覆盖所有重要的质量方面
4. **实用性**：避免过于复杂或冗余的检查项

## 相关命令

- `/sdd.analyze` - 分析文档质量
- `/sdd.implement` - 执行实现
- `/sdd.clarify` - 澄清模糊事项
