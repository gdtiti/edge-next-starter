description: 澄清规范或计划中的不明确事项
---

## 用户输入

```text
$ARGUMENTS
```

你必须考虑用户输入后再继续（如果不为空）。

## 概述

澄清命令用于识别和解决规范、计划中的模糊事项，确保所有细节都足够明确以支持实现。这个命令会：

1. **模糊点识别**：扫描文档中的不明确表述
2. **问题分类**：按影响程度对问题进行分类
3. **解决方案**：为每个问题提供可能的解决方案
4. **决策支持**：帮助用户做出最佳选择

## 执行流程

### 1. 文档扫描
扫描以下文档中的模糊表述：
- **功能规范**：`spec.md`
- **技术计划**：`plan.md`
- **数据模型**：`data-model.md`
- **API 契约**：`contracts/`

### 2. 模糊点识别

#### 常见模糊表述
- "合适的" → 具体的标准是什么？
- "良好的" → 可衡量的指标是什么？
- "快速" → 具体的响应时间要求？
- "安全" → 具体的安全标准？
- "用户友好" → 具体的用户体验要求？

#### 澄清标记
```
[NEEDS CLARIFICATION: 具体问题]
```

### 3. 问题分类

#### 按影响程度分类
- **高影响**：影响功能范围或安全
- **中影响**：影响用户体验或性能
- **低影响**：影响实现细节或优化

#### 按类型分类
- **需求模糊**：功能需求不明确
- **技术模糊**：技术选择不明确
- **约束模糊**：性能或安全约束不明确
- **验收模糊**：验收标准不明确

### 4. 解决方案生成

#### 为每个问题提供选项
```markdown
### 问题 N: [问题标题]

**上下文**: [相关文档内容]

**需要明确**: [具体需要澄清的问题]

**建议选项**:
| 选项 | 解决方案 | 影响 |
|------|----------|------|
| A | [方案A] | [影响说明] |
| B | [方案B] | [影响说明] |
| C | [方案C] | [影响说明] |
| Custom | 自定义方案 | [说明] |

**推荐**: [推荐选项和理由]
```

## 输出格式

### 发现澄清事项
```markdown
# ❓ 发现澄清事项

## 扫描结果
扫描了 4 个文档，发现 3 个需要澄清的事项

### 高影响问题 (1 个)
这些问题影响功能范围或安全性，必须澄清

### 中影响问题 (1 个)
这些问题影响用户体验或性能，建议澄清

### 低影响问题 (1 个)
这些问题影响实现细节，可选澄清
```

### 具体问题示例
```markdown
### 问题 1: 性能要求不明确

**上下文**: 
> "系统应该具有良好的性能"

**需要明确**: 
具体的性能指标是什么？响应时间、并发量、吞吐量？

**建议选项**:
| 选项 | 性能指标 | 影响 |
|------|----------|------|
| A | 响应时间 < 500ms，并发 1000 | 标准要求，实现适中 |
| B | 响应时间 < 200ms，并发 5000 | 高性能要求，技术挑战 |
| C | 响应时间 < 1s，并发 500 | 基础要求，容易实现 |

**推荐**: 选项 A - 平衡性能和实现复杂度

### 问题 2: 用户权限级别不明确

**上下文**:
> "用户应该有不同的权限级别"

**需要明确**:
具体有哪些权限级别？每个级别的权限是什么？

**建议选项**:
| 选项 | 权限设计 | 影响 |
|------|----------|------|
| A | 管理员/普通用户 二级权限 | 简单，适合小系统 |
| B | 超级管理员/管理员/编辑者/查看者 四级权限 | 细粒度控制，复杂度高 |
| C | 基于角色的权限控制 (RBAC) | 灵活，需要权限管理界面 |

**推荐**: 选项 C - 可扩展性好，适合长期发展
```

## 使用示例

### 基本澄清
```bash
/sdd.clarify
```

### 针对特定文档
```bash
/sdd.clarify spec.md
```

### 针对特定类型
```bash
/sdd.clarify --type performance
```

## 注意事项

1. **优先级排序**：先澄清高影响问题
2. **提供选项**：不要只提问，要提供解决方案
3. **推荐建议**：基于最佳实践给出推荐
4. **记录决策**：将用户选择记录到相应文档

## 相关命令

- `/sdd.specify` - 创建功能规范
- `/sdd.plan` - 制定技术计划
- `/sdd.analyze` - 分析一致性
